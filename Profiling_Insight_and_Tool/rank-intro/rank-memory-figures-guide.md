# Rank 显存柱右侧三图怎么看

适用页面：`rank-intro.html`

## 先说结论

页面代码中的 `rm-fig` 只是一个样式类名，可以理解为 **Rank Memory Figure（Rank 显存说明图）**。它不是一种算法，也不表示三份额外的显存。

点击显存柱、再点击右侧显存账单中的某一项后，出现的几张图是在从不同角度解释同一块显存：

| 图 | 它回答的问题 | 可以把它想成 |
| --- | --- | --- |
| 第一张：成分占比图 | 这块显存里装了什么，谁最占空间？ | 购物清单 |
| 第二张：三维切分图 | 完整模型这么大，本卡具体拿了哪一片？ | 切蛋糕 |
| 第三张：训练关系链 | 它在训练的哪一步产生、使用和释放？ | 流水线 |

简单记忆：**第一张看组成，第二张看切分，第三张看生命周期。**

## 点击过程是什么意思

1. 点击中间的一根显存柱，选中一张卡，也就是一个 `Rank`。
2. 右侧出现这张卡的显存账单，包括权重、梯度、优化器态、激活、碎片/预留。
3. 再点击账单中的一行，下面展开 `rm-fig`，解释这一档显存为什么会出现在这张卡上。

这里的 `Rank` 不是“排行榜里的名次”，而是一个训练进程。入门时可以近似理解为“一张加速卡上的一个工作进程”。

## 第一张：成分占比图

点击权重、梯度或优化器态后，第一张通常是若干横条，例如：

- `experts · EP`
- `attn.q · TP`
- `attn.kv · TP`
- `router · 复制`

每行右边还会显示实际占用量和百分比。

### 怎么看

- 横条越长，说明这个组成部分占用的字节越多。
- GB 或 MB 是它在当前 Rank 上实际占用的大小。
- 百分比表示它在这一整档中的占比。
- `TP`、`EP` 表示这个张量被哪一种并行方式切分。
- `复制`表示它没有被切开，相关 Rank 各自保存一份完整副本。

这张图中的颜色主要表示“哪把并行刀切了它”：

- 青色：TP，通常沿隐藏维、注意力头等方向切分。
- 紫色：EP，沿专家编号切分。
- 灰色：没有切分，直接复制。

例如 `experts · EP` 的横条很长，意思是：

> 专家权重占了这一档显存的大部分，并且专家权重按照 EP 分配到了不同 Rank 上。

它并不是说“EP 很慢”或者“紫色就是异常”。

### 为什么梯度和优化器态也显示类似构成

每个参数通常都有对应的梯度和优化器状态，因此它们基本跟随权重的内部结构和切分方式：

- 权重：模型现在使用的参数值。
- 梯度：反向传播计算出的参数修改方向。
- 优化器态：优化器为了更新参数而长期保存的辅助数据，例如主参数、动量 `m`、二阶矩 `v`。

所以点击梯度或优化器态时，第一张图仍然借助权重的组成来说明“这些字节分别属于哪些参数”。它们的相对比例可能相似，但总字节数并不相同。

## 第二张：三维切分盒子

这张图看起来像透明魔方，但它不是物理机箱，也不是显存的真实形状。它是一个表示模型如何被切开的“逻辑蛋糕”。

对于权重、梯度和优化器态，三个方向表示：

- `ℓ`：Layer，即模型层，由 PP 分段。
- `h`：隐藏维或注意力头，由 TP 切分。
- `e`：专家编号，由 EP 切分。

图中的摆放方向与主 Rank 矩阵一致：

- 横向：EP 分桶。
- 上下：TP 分片，和主矩阵一样是 TP0 在上、TP1 在下。
- 纵深：PP Stage，**从近到远是 PP0 → PP1 → PP2 → PP3**。

选中块不会被“抽出来”单独展示，它以半透明填色待在 PP、TP、EP 三个坐标共同划给当前 Rank 的格子里。切分线和外框压在填色块上方，是为了让所属格腔更容易辨认。

当前页面的默认配置是：

- PP = 4：48 层分为四段，每段 12 层。
- TP = 2：隐藏维相关张量通常被切成两片。
- EP = 8：64 个专家被分成八桶，每桶 8 个专家。

### 实心格和虚线格

- 实心、高亮的格子：当前选中的 Rank 实际持有的那一片。
- 其他虚线格子：完整模型的其他分片，由其他兄弟 Rank 持有。

可以这样理解：

> 大模型无法全部塞进一张卡，于是先按层切，再按隐藏维切，再按专家切。当前 Rank 只拿三种切分交叉出来的那一格。

这里 PP 更多是在决定“这张卡负责哪一段 Layer”，而不是把同一个张量简单地横切成四份。

## 权重究竟按 Layer 分，还是按 PP Stage 分

准确说法是：**权重从业务语义上属于具体 Layer，再由 PP Stage 接管一段连续的 Layer。**

这不是两个互相排斥的答案，而是两个层次：

1. 模型定义层：每个 Transformer Layer 都有自己的 Attention、Router、Experts、Norm 等权重。
2. 设备放置层：PP 把连续的 Layer 分段，把每一段交给一个 PP Stage。
3. Stage 内部：该段里的权重再由 TP、EP 切成分片，并由 DP 或 EDP 保存副本。

以页面默认的 48 层、PP=4 为例：

| PP Stage | 负责的 Layer |
| --- | --- |
| PP0 | L0–L11 |
| PP1 | L12–L23 |
| PP2 | L24–L35 |
| PP3 | L36–L47 |

因此可以说“PP0 保存 L0–L11 的权重”，但不应该理解成“PP0 内每个 Rank 都保存 L0–L11 的全部权重”。

### 同一个 PP Stage 内，所有 Rank 的权重一致吗

**不一致。**它们负责相同的 Layer 范围，但持有的可能是不同分片，也可能是同一分片的副本：

- Attention 的 Q、KV、输出投影等：按 TP 切分。TP0 和 TP1 持有不同切片；相同 TP 坐标的 DP 副本在同步后数值一致。
- Experts：按 EP 切分。不同 EP Rank 持有不同专家桶。
- Router、Norm：页面当前口径中不切分，会在相关 Rank 上复制。
- Embedding：只在 PP0，并按 TP 切分。
- LM Head：只在最后一个 PP Stage，并按 TP 切分。

在这个演示配置里，专家数、隐藏维等都能均匀切开，所以同一 Stage 中很多 Rank 显示的“权重 GB 数”会相同。但那只表示**分片大小相同**，不表示张量内容相同。例如 TP0 和 TP1 都可能显示相同 GB，却分别拿着同一权重张量的不同切片。

默认配置里 ETP=1，专家本身不再按 TP 切。因此，同一专家桶会在两个 TP 对片和相应的数据副本上重复保存；这些副本由 EDP 梯度同步保持一致。

一句话总结：

> 同一 PP Stage 的 Rank 拿的是同一段 Layer 的工作，但不等于拿着完全相同的一包权重；是否相同，要继续看它们的 TP、EP、DP/EDP 坐标。

### 点开权重内部小块时怎么看

如果继续点击权重内部的某个小块，例如 `attn.q`、`experts` 或 `router`，图会只突出与它有关的切分轴：

- `attn.q`：主要由 TP 切分。
- `experts`：主要由 EP 切分。
- `router`、`norm`：可能不切，相关 Rank 保存副本。

因此，不是每一个张量都会同时被 PP、TP、EP 三种方式切开。

## 第三张：训练关系链

第三张图用三行说明几类显存对象在一次训练中的关系：

```text
前向：激活 A × 权重 W → 输出
反向：输出梯度 × 激活 A → 权重梯度 ∇W
更新：优化器态 + 梯度 ∇W → 新权重 W(t+1)
                                      ↓
                                  下一步的 W
```

这张图的重点不是展示严格的数学公式，而是回答“这一块显存为什么要存在、什么时候会被使用”。

### 怎么看

- 颜色最实、边框最亮的方块，是当前点击的显存类型。
- 较淡的彩色方块，是与它有关的其他显存类型。
- 虚线框通常是计算结果或中间量，但不属于右侧列出的那五档显存账。
- 图中的淡色显存方块可以点击，用来跳到对应的显存项。

### 点击不同项目时的含义

点击“权重”时：

- 前向计算需要读取权重。
- 更新阶段会改写权重。
- 更新后的新权重进入下一次训练迭代。

点击“梯度”时：

- 梯度在反向传播阶段产生。
- 优化器在更新阶段使用梯度。
- 更新完成后得到下一步的新权重。

点击“优化器态”时：

- 前向和反向一般不会直接使用它。
- 它主要在参数更新阶段工作。
- `m`、`v` 等状态需要跨训练步保留，所以即使当前不更新，它也一直占用显存。

点击“激活”时：

- 激活由前向计算产生并保存。
- 反向计算还要使用它计算梯度。
- 反向使用完毕后，它才可以释放。

## 点击“激活”时，三张图会不一样

激活是随训练时间变化的临时数据，不是长期固定的模型账。因此点击激活后，三张图变为以下含义。

### 1. 激活切分盒子

它表示激活大致沿这些方向分布：

- `ℓ`：激活属于哪一段 Layer，由 PP 决定。
- `s`：序列方向，可能由 CP 切分。
- `b`：不同的数据批次或 DP Rank 各自处理的数据。
- `h`：隐藏维。此页面的说明中，算子之间会通过 AllGather 恢复到全长，因此不把 TP 画成激活体的长期切分轴。

实心格仍然表示当前 Rank 持有的部分。

### 2. `in-flight μb` 小格图

`μb` 是 micro-batch，即微批次。小格数量表示这个流水线阶段当前压着多少份还没有完成反向传播的微批次激活。

页面使用 1F1B 流水线。默认情况下，各 Stage 的在途数依次是：

```text
Stage 0：4 份
Stage 1：3 份
Stage 2：2 份
Stage 3：1 份
```

越靠前的 Stage，通常需要等待越久，暂存的微批次激活也越多，所以激活显存压力往往更大。

这些格子主要用来表达“同时压着几份”，不要把每一个格子误认为一张新的物理卡。

### 3. 训练关系链

第三张仍然是前向、反向、更新关系链，此时会重点高亮“激活”：前向留下，反向消费。

## “碎片/预留”为什么图比较少

碎片/预留不是模型参数，也没有像 TP、PP、EP 那样稳定的张量切分关系。它主要包括：

- 显存分配器造成的碎片。
- 算子临时使用的 workspace。
- 框架或运行时提前预留的空间。

因此点击它时，页面只需要说明“没有切分轴，也不参与这些并行刀”，不一定会完整显示三张图。

不同 Rank 的执行历史不同，碎片/预留也可能不完全相同。

## 最快的阅读方法

以后看到右侧这些图，只问三个问题：

1. **谁最大？**——看第一张横条和百分比。
2. **本卡拿了哪一片？**——看第二张盒子里的实心格。
3. **什么时候产生和使用？**——看第三张的前向、反向、更新。

最后再看图下方的“对应通信”和“兄弟卡”说明：

- “兄弟卡”告诉你，哪些 Rank 与当前 Rank 的分片可以共同拼成更完整的数据。
- “对应通信”告诉你，为了计算或同步，这些 Rank 之间需要执行什么通信。

所以整套右侧说明的阅读顺序可以归纳为：

> 先看占多少，再看怎么切，接着看何时使用，最后看需要跟谁通信。
