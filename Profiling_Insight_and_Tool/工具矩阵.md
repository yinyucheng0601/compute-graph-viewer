# 附录：常见问题 → 用哪个工具的哪张图解释

面向业务小白用户的「xxx 问题该拿什么图讲」速查表。原则：**结构性 / 配置性的「为什么会这样」用 Config & Relation Observer（含平面视图）的容量分段图讲；空间上「落在哪张卡」用 op-rank-time-wzhBranch 的 3D 映射讲；运行中「哪张卡出事、怎么出的事」用 Training Run Explainable Twin 的热力矩阵 + 定位链讲；真实数据核对交给 MindStudioNext v3 的 HBM 快照。** 后续遇到新问题按同一格式追加。

## 内存 / 显存类

| 问题 | 首选工具 · 图表 | 为什么是它 | 补充工具 |
| --- | --- | --- | --- |
| 某 rank 为什么 OOM | **Training Run Explainable Twin** → 「问题诊断」里的「显存 OOM」卡 + 聚光灯定位链（6 张举证图：显存曲线爬升、峰值超标 + 分配器碎片双因子判据等） | 唯一把 OOM 做成「表象 → 证据 → 根因」逐层讲故事的页面，左侧架构图同步高亮出事的那张卡，小白不用自己读数字 | 回到 **Config & Relation Observer** 的「单卡容量」等距投影图，看这套配置下该卡本来就贴着 HBM 上限还是有余量（越界判定一眼可见） |
| optimizer state 为什么异常占内存 | **Config & Relation Observer** → 「单卡容量」分段柱（权重 / 梯度 / 优化器状态 / 激活四段） | 页面直接给口径：Adam 优化器状态 = fp32 master weight + 两个 moment ≈ 12 B/参数，是权重段的好几倍；拨「关 / ZeRO-1 / FSDP2」三档，能看到优化器段随 ÷DP 缩小 —— 亲手体会「不切就是异常大」 | **MindStudioNext v3** 的 HBM 显存快照，看真实 run 里优化器张量的实际占比做对照 |
| TP/PP 为什么改变 activation/gradient footprint | **Config & Relation Observer · 平面视图** → 中间无限画布 + 「各 PP Stage 峰值」 | 平面视图把 TP/PP/DP/CP/EP 和配置项摆在同一张矩阵里：改 TP 看激活段按 TP 切分，改 PP 看每个 stage 只持有一段层且峰值随 1F1B 暖启动阶段不同而不同；叠加 `recompute` 四档看激活段再被重计算压下去 | **op-rank-time-wzhBranch** 的 1F1B chunk-level 调度泳道，解释「PP 为什么要囤好几个 micro-batch 的激活」这一时间维度的原因 |
| shard 到底落在哪个 rank | **op-rank-time-wzhBranch** → 3D 场景（正视 / 轴测）的模型层 × rank 映射 + 对象聚焦（Layers / Communication / Hardware） | 唯一把「某一层的某个算子 / 专家落在哪张卡」画成空间对应关系的页面，点 rank 就能看它持有哪些层、参与哪些 TP All-Reduce / EP All-to-All 组 | **Config & Relation Observer** 的一个 step 数据流播放，从配置角度看 DP×PP×TP×EP 的切分顺序（`world_size` 如何被分解） |
| checkpoint 为什么产生额外内存 | **Config & Relation Observer** → 「单卡容量」+ ZeRO-1 / FSDP2 三档切换 | 页面文案已解释：FSDP2 存 checkpoint 需 all-gather 回完整权重、ZeRO 分片状态保存时要临时聚合，都会在正常四段之外多出一段瞬时峰值；对照三档看「切得越细、保存时临时聚合越多」 | **Training Run Explainable Twin** 的「时光全景」浮窗，在时间轴上定位 checkpoint 事件与显存尖峰的重合 |
| 某个 rank 为什么和其他 rank memory 不一致 | **Training Run Explainable Twin** → 集群热力矩阵（跨卡显存占用） + MoE 专家负载（Router 倾斜）卡 | 热力矩阵先让小白一眼看出「哪张卡颜色不一样」；再点专家负载卡，多数不一致来自 EP 路由倾斜（热门专家所在 rank 收到更多 token）或 PP 首末 stage 多持 embedding / logits | **Config & Relation Observer** 的「各 PP Stage 峰值」看结构性不一致（stage 0 / 最后一个 stage 天然更重）；**MindStudioNext v3** HBM 快照做单卡精查 |
