#### 训练时，如果都是 5~10 个字的短句，比如就是 10 个 token ，但如果 BSH=8，2560，4096，那数据样本怎么凑 8，2560，4096？

10远小于2560，因此主流做法是拼接，比如那256个语料凑齐2560这个token序列，并且继续凑，凑8份，把NPU用得满满当当明明白白的。

只有SFT的时候不会拼凑，而是填padding，也就是一个10token的语料要填2550个padding。

#### 有时和AI聊着聊着就提示接近上下文窗口限制了。这个和每次对话的seq有什么关系？

上下文窗口限制，就是模型当前这一次推理所允许的最大有效序列长度S_max。

openPangu2.0flash为例
序列长度4096，最大上下文512k（512K = 512 × 1024 = 524288 tokens）。如果每次对话消耗 1000 tokens，预计可以聊500轮。

这里的最大有效序列长度只指单次申请，而不是累计。比如聊到第10轮，S为1000+9*1000=10000 < 524288，放行！




#### Embeding 权重表

类似一个人掌握的词汇量和对词汇的理解。openPangu的词权重表大小是15万，形状是[151552, 2560]，一个token一个坑，一个token（比如“喜欢”）就是151552行中的某一行，一个长度 2560 的一维向量，即隐藏维度。这2560个数字最终表示了单个token的实质“含义”。隐藏维度越大，理论上单个token可以存储的信息量更丰富。

>注：分词器也叫词表，只负责把语料拆成多个token，这个表随着训练进行是不会被更新的。

每个token进入模型后，会先在Embedding层查出自己的2560个数字，这个数字在每一层都会被计算一次。用新的结果进入下一层。

每个step的最终，反向阶段传回的梯度，也有emb的部分，更新这个词表中本step涉及到的token的2560数字。

序列长度：一次xx处理多少token，常见4096。

#### 模型中的张量一定都是2维的吗？
不一定，比如：
Norm权重：1维
Linear权重、Embedding权重：2维
注意力激活：常见4维

#### Tokenizer实际编码  遇到苹果时能切“苹”“果”，遇到“苹果手机”时，切“苹果”“手机”，它怎么知道苹果要单切还是切一起？
有固定算法，但是不一定精准

#### 遇到“苹果手机”时，切“苹果”“手机”，遇到苹果派时切“苹果”“派”。虽然都切成“苹果”但含义不一样，这两个含义的苹果在词表都是同一套隐藏维度矩阵吗？
同是“苹果”，查出来的Embedding的[2560 × 2560]数字编码是一样的，他们语义的差异关键在训、推时和其他词形成的上下文，产生不同的隐藏状态表达不同含义。Embedding保存的是“苹果”的通用起点，具体语义主要由多层注意力和上下文共同形成。


# 并行切分

#### openpangu为什么不全是MoE层，非要在前面加2层Dense层？

因为可以让进入模型的token经过Dense稠密FFN后更有初始上下文信息，更有区分度的进入专家区

#### EP居然有多重理解，需要小心对号入座

我们对EP的理解之所以困难，因为它虽然都被写成“EP”，实际可能有3个含义，一旦对不上号，搞错了对方说的是哪个EP概念，大脑马上宕机。

- 当EP表示一种并行策略的时候，实际说的是“**Expert Parallelism**”
- 当EP表示专家并行度，即**一套完整专家**被分到多少个 rank 上时，实际说的是“**EP size / degree**”
- 当EP表示参与这次专家切分和通信的 rank 的集合时，即**执行一次专家 all-to-all 通信的一组 rank**的时候，实际说的是“**EP group**”，由于一套完整的专家要“EP”个Rank，但你很**富裕**，训练用了8倍“EP"个Rank，那EP group=8.


所以当有人说“EP”时，你要先反问“你说的是哪个EP？”

注：EP本身不切专家的权重，都按专家“人头”进行分组，如果专家权重被切了，那是TP干出来的事。

注：把EP组理解成一个EP有xx个专家是错误的，他只描述涉及xx个Rank，不用来描述有多少个专家，描述对象有明显不同。EP Group也是以Rank为对象。

#### EP切分关键算式

无论是EP正交还是EP切出（主流），**每个Rank的专家数（experts per EP rank）都是 = Experts ÷ EP**，
即
“正交”和“切出”不会改变一套专家内部的EP切分方式，不会改变上述公式。

Total Routed Expert=256，EP=64 为例：

- 从Expert Parallelism的角度，表示一套专家要进行切分。EP size则是Expert Parallelism的具体执行方式。
- 从EP size=EP=64的角度，表示是专家会分布在 64 个 rank 上。（注意，这里不是说1“完整专家”在64个rank上，假如tp>1，64个rank只能有一套专家的分片）
- 由上也可知，experts per EP rank，即每个 rank 放置 256 ÷ 64 = 4 个专家。

>如果TP从1改成2，势必提升一倍total rank数，全套专家也依然分布在 64 个rank上，每个rank 4 个专家，只是这时，每个rank只有 4 个专家的1/2个分片。那问题来了，TP从1改成2，EP Group 依然是 64 rank，还是128rank呢？答案是64rank，因为此时all to all **不是在128个rank之间alltoall**，输入的token被复制成2份，流入2个tp，单个tp内all to all计算通信，流出2个tp时再TP collective

- 从EP group 的角度，当前64个Rank是一个EP Group。如果你出资128个Rank，那EP group count=2，那DP必须拉上2。反过来，当你EP设为64，但只肯出32个Rank，小于EP，模型也跑不起来。

>疑问：如果一个stage有4个layer，每个layer上的完整专家是不一样的吧。那一个rank要支撑起一个stage的4个layer的话，这个rank上只有4个专家（这样会理解层每个layer都复用这4个专家），还是有4 x 4(layer)=16个专家？
>答案：16。当你有4个moe layer时，一个模型才不是256个专家，而是4 X 256专家。一个承载4个layer的rank，为每个layer都分别存了各自的4个专家。


#### EP切出和EP正交的区别？

EP切出（主流）
就是EP切片和DP的切片会一起混放到Rank上。DP和EP必须呈倍数关系，且DP必须大于等于EP。DP/EP等于多少，就一共多少套专家。

可以简单理解为，比如512个DP分片站在一起商量，每64个DP分片拼团一套专家，那一个模型（512个DP分片）一共拼8套专家。

#### 是不是一个模型就8套专家

不是，openpangu2.0flash 有44个MoE层，就有44套完整专家。

每一个DP所在的Rank上虽然专家不全，但是可以跨DP共用其他DP的专家，形成一个EDP组，一个EDP组有一套完整的专家，一共8个EDP组。
同样的rank数下，DP可以自然切更多，因为他不需要EP正交那样疯狂复制自己（去迎合EP切分）而占了很多rank。
最终DPxPP=Total Rank

EP正交（也要EP切入）：
因为完整专家被切了64份，所以每一个DP还需要【重复】复制自己64份（很占Rank），给64套专家分片去计算，64份计算结果合成一套完整专家计算结果，不然覆盖不全专家。
这种方式下，DP间专家隔离。一共有几个DP，一个模型就有几套专家。
同样的rank数下，DP不得不更小，不然DP重复自己后很难放得下，DPxPPxEP=Total Rank

Layer角度
Layer间专家隔离，每个Layer必须有一套完整专家。Layer自然要靠一个Stage所有Rank支撑起这一套专家。
一个 layer 横跨一个 stage 所有 rank。
一个 rank 会承载一个 stage 所有 layer 的部分或全部权重（比如router / norm 的权重无论怎么切分，恒为完整拷贝）
进一步说
Stage1的L12~L23一共12层layer，每个layer都会横跨Stage1的所有Rank
如果要设立4个Stage，那就要4倍的Rank
所以Total Rank的计算要 xPP

一个layer有没有一套完整的专家？
每个layer有一套完整专家，那moe x 44层理论上就有44套完整专家。但EP切出一共8套完整专家，EP正交一共也8套完整专家。44和8就对不上？
这里理解有误，首先，这个模型真正有44套专家（44套专家权重）
正交和切出中的DP8，和EDP8，指的是在一个layer下，8套专家在8个DP\EDP同时工作
一个rank下的moe token，它可能来自8个dp，假如他来自第一个dp，那它all to all 时，会和stage内所有rank通信一遍

# 漫画

创作一页生动、有故事感的黑白教育漫画，主题是：

《巧说模型训练》

【整体画面】

一张竖版漫画，上、中、下4幅横向分镜，4幕高度接近，使用粗黑分镜边框，从左向右阅读。

风格为专业黑白漫画：

- 纯黑墨线和白色纸张

- 少量灰色网点、排线和速度线

- 人物表情夸张、生动、有幽默感

- 所有角色在四幕中保持相同的脸、服装和名牌



【固定角色】

1. 最左侧一名穿条纹裁判服的裁判，胸前挂着大号名牌：

“数据集”

2. 数据集裁判的右侧，四名穿运动背心的运动员，从左到右站在同一个水平的站台上。站台正面写着：“NPU”

四名运动员衣服上，分别贴着清晰名牌：

“layer0”

“layer1”

“layer2”

“Norm+Head”

3. 画面上的高台右侧站着三名穿条纹裁判服的裁判，胸前分别贴着名牌：

“loss计算”

“梯度计算”

“优化器”

四幕中角色身份不得互换，不得增加或减少人物。

────────────

【第一幕】

分镜标题：

“正向传播：逐层处理数据”

画面最左边，“数据集”裁判拿着谜语卡，卡片背面写着标准答案“月亮”。他大声出题：

“什么东西每到了晚上才在天上出现，有时圆有时两头尖，有云时就看不见？”

画面左侧前3名运动员在“NPU”站台上依次面向画面右侧的人传递谜语，第四名运动员“Norm+Head”不再传话，而是根据layer2传来的谜语，面向loss裁判猜答案。

前三段传话和最后一次猜谜都用相同样式的气泡框起来。

layer0喜欢把语序颠倒。他一边掰着手指一边面对着layer1说：“到了晚上才在天上出现，有时两头尖、有时圆，有云时就看不见，是什么？”

layer1总是理解错意思。他自信满满、完全没有意识到自己传错了，转身面对着layer2说：“什么东西晚上吃饭时才有，有时是圆的，和云不会同时出现？”

layer2经常漏字。他表情迷糊。转身面对着norm+head说：“吃饭时出现，圆圆的，很大，和云一样的颜色”

“Norm+Head”举手猜道：“我猜是……盘子！”

画面右侧的loss、优化器、梯度计算三明裁判露出吃惊表情。


────────────

【第二幕】

分镜标题：

“反向传播，loss与梯度计算”

台下三名裁判围拢在一起讨论，像比赛暂停时分析录像。画像卡在裁判上半身，这一幕不出现4名运动员。

“loss计算”裁判手中同时拿着标准答案“月亮”和猜测答案“盘子”。和其他两个裁判说：“猜测答案和标准答案差异80%！”

“梯度计算”裁判说：“为了让Norm+Head答案更接近月亮，倒过来推，layer2少漏关键词，layer1更精准还原意思，layer0少倒序。”

优化器裁判不说话，在旁边记录梯度计算裁判的意见到记录板

────────────

【第三幕】

分镜标题：“按梯度一口气优化权重”

贴着“优化器”名牌的裁判，拿着刚刚的记录板，站在沿着“NPU”站台前，他对着所有运动员说：“layer0注意不要倒序！layer1注意准确还原意思！layer2注意别漏关键词！Norm+Head注意综合全部线索再猜！”

四名运动员认真听取建议，没说话，都在认记录。

────────────

【第四幕】

分镜标题：

“下一轮，更“聪明”了”

“数据集”裁判换了一张新的谜语卡，卡片背面写着标准答案“时钟”，说：“什么东西没有嘴却会报时，没有腿却一直走，挂在墙上滴答响？”

经过第一轮纠正后，四名运动员这次更加认真、专注、配合默契，谜语在第二轮传递得准确多了。他们收起了记录本。

layer0不再倒序，转身面向layer1说：“什么东西没有嘴却会报时，没有腿却一直走，挂在墙上滴答响？”

layer1不再改变原意，转身面向layer2说：“什么东西没嘴会报时、没腿会走，还挂在墙上滴答响？”

layer2仍然漏掉了一点信息，但比第一轮好很多，转身面向norm+head说：“没嘴会报时，没腿会走，还会滴答响，是什么？”

“Norm+Head”综合关键词认真思考后，给出一个已经非常接近标准答案的猜测：“我猜是……时钟！”

台下的“loss计算”裁判兴奋地跳起来，他说：“和标准答案的差异度降到20%！”

旁边的“梯度计算”和“优化器”裁判不说话。他们同时转头看向漫画外的读者，挑起眉毛，露出会心的微笑，形成一个幽默的漫画停顿，仿佛在说：“你品品。”
