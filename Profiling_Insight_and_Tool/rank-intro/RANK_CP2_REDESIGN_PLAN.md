## 目标与固定口径

- 总规模保持 128 Rank、16 台 node，每台 8 Rank；48 层分为 PP=4，每段 12 层、32 Rank。
- Rank 页签的教学基线从 `PP4 × DP16 × TP2 × CP1` 改为 `PP4 × DP8 × CP2 × TP2`。EP 从 DP 切出，改为 EP=4、EDP=2、ETP=1。
- 先保留 TP 为最低位的编号习惯：`rank = pp×32 + dp×4 + cp×2 + tp`。同一 DP 内，R0/R2 是横排的 CP 对片，R0/R1 是纵向的 TP 对片。每台 node 容纳两个完整 DP 四卡组。
- CP 沿 S/token 切分，同一 DP 内 CP0/CP1 处理同一批样本的不同上下文区间。CP 不增加独立数据副本，也不切专家权重。
- 插入步骤后顺序为：01 Rank、02 node、03 cluster、04 PP、05 DP、06 CP、07 TP、08 EP、09 内存、10 通信、11 展平视图。

## 分阶段修改清单

### 第一阶段：05 DP 与新增 06 CP

- 第 05 步改为 DP=8、每 PP 段 8 个四卡组；文案、蓝色分组和 DP0–DP7 门牌同步。
- 在 05 后插入绿色 06 CP。每个 DP 四卡组分为横排的 CP0/CP1 两组，每组暂含两个尚未展开的 TP Rank；给出 S 前半／后半的说明、绿色分组高亮和 CP 门牌。
- 让步骤导航、顶部维度直达和 `?step=6` 指向新增步骤。06 完成时曾暂留旧版 07–11 的内部逻辑；07、08 的排布已在下一阶段更新，09–11 仍不能当成已完成的新口径。

### 第二阶段：07 TP 与 08 EP

- 第 07 步在每个 CP 位置纵向分出 TP0/TP1，形成横向 CP2 × 纵向 TP2 的四卡块；TP0/TP1 与 CP0/CP1 都按 DP 列各标一对、跨 PP 复用。更新动画、门牌、相机比例和 Rank 选择。（展示与门牌已完成。）
- 第 08 步 EP4 在同一 PP、EDP、CP、TP 坐标下，以 DP0–DP3、DP4–DP7 分别组成四卡通信组。每个 PP 段有 `EDP2 × CP2 × TP2 = 8` 个 EP 通信组，全网 32 个；每 Rank 每 MoE 层持有 16 个专家。相同 EP 位置在两个 EDP 实例中是独立副本。（展示、逐组高亮、一组一个且无副标题的 EP 门牌和 Rank 详情已完成。）
- 将 Rank 对象、编号反解、EP 组与专家归属统一改为明确的 `pp/dp/cp/tp/ep` 坐标，替换旧的 `dp>>3`、`dp&7` 等隐式位运算。

### 第三阶段：09 内存与 10 通信

- 第 09 步按本地 `S/CP` 计算和标注激活；在激活图中同时表达 CP token 区间、TP hidden 分片与 EP 路由后的 token 桶。rankmem 激活行标出本卡 CP 位置，固定内存区说明 CP 对片各有一份参数；权重和优化器态仍按实际参数分片／副本归属展示。（主视图、显存账和五个内存场景已完成；MBS2、HBM128 GB。）
- 新切出口径下完整专家副本数 `EDP=DP/EP=2`；保留两个独立数据副本，但按新编号重算 EDP、EP 位置与对应 Rank。相同专家分片在 CP 和 ETP=1 的 TP 坐标上也有物理副本；专家梯度须按真实同步域处理。
- 第 10 步加入绿色 CP 通信维度、对端、线型、流量和时间线；按每组 4 Rank、EDP2 重算 TP、EP、DP、专家梯度、PP 的对端集合与通信量。明确 CP 注意力交换与 CP 参数梯度同步属于不同阶段。
- 复核 R23×L7 OOM、EP 路由倾斜、R87 通信长尾等固定案例。09 的 R23 仍为热点主语，但已改为 CP1 / EP组7、每卡 E16–E31；10 通信案例仍待迁移。

### 第四阶段：11 展平视图与跨页签核对

- 纵轴保持每 PP 段 32 行，但按 `DP8 × CP2 × TP2` 重排；增加 CP 层级和颜色，核对 EDP/EP/CP/TP 标签与 Rank×Layer 详情。
- 配置预览基线改为 DP8、CP2、EP4、EDP2；更新口径切换换算、自动演示、预设查询、容量与热力计算。共享规则层的 `world` 已计入 CP，但展平行数及组高目前没有计入 CP，需分别改造并验证其他调用方。
- 统一主页面步骤索引、顶部控制、URL、播放器、侧栏、显存周期和配置预览的入口，不遗留旧“第 10 步”或旧索引。
- Shard 页签目前采用 DP4×CP2×TP2×PP4 的 64 Rank 示例。先对齐轴的含义和编号顺序；若还要求数值完全一致，则另将其改成 DP8×CP2×TP2×PP4、EP4/EDP2，并重做 B=8 的分样本及 EP 选项。

## 验收要点

- 任一 Rank 都能唯一反解为 `(pp,dp,cp,tp)`；每 PP 段 32 Rank，每 node 两个完整 DP 四卡组，全网 128 Rank。
- 05 显示 8 个 DP 四卡组；06 每组显示两个横向 CP 子组，绿色高亮与 CP0/CP1 标注一致；07 在各 CP 子组内竖向叠 TP。
- 08 EP 组固定 PP/EDP/CP/TP，分别横跨 DP0–DP3 或 DP4–DP7 的 4 个 DP；09 激活只占本 CP 的 token 区间并区分两个 EDP 副本，且 128 GB 容量溢出显示准确；10 CP 通信对端正确；11 行数和 Rank 详情一致。
- 检查 `?step=6`、前后导航、缩放和不同机位；核对旧事故案例不会因 Rank 角色变化而给出错误结论。

## 需要保留的设计取舍

- EP8→EP4 使 `DP8/EP4=EDP2`，因此两个 EDP 实例分别处理独立数据；CP0/CP1 仍只是同一 DP 数据的 token 对片，不能算额外数据副本。
- DP16→DP8 后，将 MBS1→MBS2、GA 保持 8，使按 DP 位置计算的全局样本数与原口径一致。
